# The catalogue is imported from the monthly Discogs data dump

`releases` holds the Electronic releases of the Discogs releases dump (CC0), loaded by `npm run db:import` (fader-ui#100). `main` stores no data from the Discogs API except what a fade lookup needs.

- **Fresh file each month, insert-only (amended for fader-ui#109):** the importer builds a new SQLite file and does not write into the live database. With `--carry-over` it first copies the old database's `releases` (and `master_versions`, which fade lookups fill) into the new file, then loads the dump with `INSERT OR IGNORE`, then builds the indexes. An existing row, enriched or not, always wins, so the dump only ever adds releases and never refreshes or removes one; a release deleted or merged on Discogs stays until an enrichment run marks it missing. `fades`, `user_settings`, `saved_filters` and `discogs_tokens` are carried over too. Without `--carry-over` the file holds the dump alone, as before. Swap it in by pointing `DB_PATH` at it with the API stopped.
- **Sample mode:** `--sample <chunks>x<MB>` reads evenly spaced chunks of the plain `.xml`, which keeps the real mix of eras (the Electronic share falls from 99% to about 20% across the file). It is for trying the app and benchmarks, not for production.
- **Shape:** title, artists, genres, styles, formats, year, country, labels `{id, name, catno}[]`, `masterId` (0 in the dump means none, stored as null), the full tracklist and videos trimmed to `{src, title, duration}`. `master_versions` is filled from the same pass.
- **Query support (fader-ui#103, #105):** `release_genres`, `release_styles` and `release_formats` hold one row per value, kept in step with the JSON columns by triggers (migration `0021`); `track_count`, `artist_sort` and `format_sort` are generated columns; indexes serve every Explore sort. On a 500k-row sample this took list queries from 0.3-0.7 s (full scans) to under 30 ms. The importer drops the indexes before the load and rebuilds them after.
- **Not in the dump:** images, ratings, haves and wants, label country. Ratings can be added per release by an enrichment run into the nullable `rating_average`, `rating_count`, `enriched_at` and `missing_at` columns (migration `0026`); Explore hides rows with `missing_at` set. See `0008-enrichment-runs.md`, which supersedes `0006-no-enrichment.md`.
- **Filter options:** the filter dialog offers a fixed list of genres, styles, formats and countries per catalogue, most common first, from the `filter_options` table that the importer (and migration `0022`) fills. `GET /releases/filter-options` serves it; there are no counts and nothing follows the current filters or what is enriched (the Enriched page offers the same list; fader-ui#112), so the old `GET /releases/facets` is gone (fader-ui#100).
