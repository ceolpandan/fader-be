# Releases are enriched from the Discogs API by a collector's run

Supersedes `0006-no-enrichment.md` (fader-ui#109). `main` fetches release details from the Discogs API again, but only when a collector asks, with their own token, for the releases of one saved filter.

- **What a run does:** `POST /enrichment/run` takes an Explore query and queues one `release_detail` job per release the filter shows that is not faded by the collector, not already enriched (unless `fresh`) and not already queued by another run. The handler overwrites the row with the API's title, artists, year, country, genres, styles, formats, labels, tracklist and videos, and adds `rating_average`, `rating_count`, `have_count`, `want_count` and `enriched_at`. Covers are not stored: every release shows the same placeholder. Releases enriched before haves and wants were stored are refreshed once by `npm run db:requeue-have-want`, which queues them as one run without the cap.
- **Own token, own lane:** every job uses the collector's token, on the collector's own queue lane (1.1 s pacing, own pause), see `0002-discogs-outage-backoff.md`. One active run per collector: starting a filter while it runs adds the filter's releases to that run (same lane, behind the queued jobs; the run keeps its first query), and `run_active` (409) remains only for the have/want backfill. Only the latest run is kept (`enrichment_runs`), cancel drops the queued jobs, and a 401/403 ends the run with "Discogs rejected your token".
- **Cap:** `ENRICH_MAX_RELEASES` limits one run (422 above it, counting only the releases that would be fetched). Production defaults to 20000, other environments to no limit.
- **Missing releases:** a Discogs 404 is retried (3 attempts); then `missing_at` is set, the release is listed on the run, and Explore hides it (list and counts). `GET /releases/{id}` still serves it. A fresh run re-fetches missing releases and clears the mark when Discogs finds them again. `POST /releases/{id}/refresh` fetches one release at once and marks it missing on the first 404.
- **Dump import:** insert-only with `--carry-over`, so enriched rows are never replaced (`0007-catalogue-from-data-dump.md`).
- **Compliance risk:** `0006` removed enrichment so that `main` stored no API data. Storing ratings and refreshed fields from the API on `main` has not been cleared against the Discogs API terms of use. This is tracked in fader-ui#108, which blocks the production release. If the review says no, remove it as `0006` describes (drop the job, the run endpoints and the columns) and restore `0006`.
- **Pointers:** the private `private-main` branch (fader-ui#102) is superseded by this and can be closed.
